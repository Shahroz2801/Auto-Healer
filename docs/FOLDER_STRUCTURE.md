# Folder structure

```
src/
  app/                         Next.js App Router
    (marketing)/                Public site: /, /pricing, /features, ... (no auth)
    (auth)/                     Clerk sign-in/sign-up catch-all routes
    (dashboard)/                Authenticated app, one folder per sidebar section
    api/                        Route handlers (webhooks, trpc, etc.)

  components/
    ui/                         shadcn/ui primitives (generated — treat as vendored)
    marketing/                  Landing page sections (hero, pricing table, ...)
    dashboard/                  Sidebar, topbar, dashboard-only chrome
    charts/                     Recharts wrappers (health gauge, trend lines, ...)
    shared/                     Cross-cutting components (empty states, etc.)

  features/                     One folder per product capability. Each owns its
                                  own components/hooks/actions, imported by app/.
    projects/
    scanner/
    ai-heal/
    ai-assistant/
    reports/
    monitoring/
    deployments/
    billing/

  server/                       Server-only code (never imported by client components)
    db/                          Prisma client singleton
    api/                         tRPC/route-handler procedures
    queue/                       BullMQ queue + worker definitions
    services/                    Business logic (scan orchestration, AI heal, billing)

  lib/
    ai/                          Provider-agnostic AI interface + adapters (Gemini, ...)
    scanners/                    SEO/perf/security/accessibility/etc. analyzers
    importers/                   URL crawl, ZIP, Git, WordPress, Shopify, FTP/SFTP/SSH importers
    validators/                  Zod schemas shared between forms and route handlers
    hooks/                       Shared React hooks
    config/                      Site config, nav config, env config (this is where
                                  `env.ts` lives — always import env from here, never
                                  read `process.env` directly in app code)

  types/                         Shared TypeScript types not owned by Prisma

prisma/
  schema.prisma                  Full data model
  seed.ts                        Demo data seed
  migrations/                    Generated by `prisma migrate dev`

docs/                            This file, ARCHITECTURE.md, INSTALLATION.md, API.md
```

## Conventions

- **Server-only code lives under `src/server/`.** Anything importing Prisma,
  BullMQ, or secret env vars belongs there or in a Route Handler — never in a
  file a Client Component can import, or the secret ends up in the browser
  bundle.
- **Feature folders over type folders.** `src/features/scanner/` holds
  everything scanner-specific (its components, hooks, server actions). Avoid
  scattering one feature across a generic `components/`, `hooks/`, `actions/`
  split — that's the layout that gets painful once the app has 15+ dashboard
  sections.
- **`src/components/ui` is generated by shadcn.** Extend via composition in
  `src/components/dashboard` or `src/components/marketing`, not by hand-editing
  generated primitives (re-running `npx shadcn add` would clobber it).
